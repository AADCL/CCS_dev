# 地面站兼容扩展说明

## 1. 范围和现状基线

本文只说明指控平台为接入端侧 `EPGeneral_multi_map` 后续需要做的兼容扩展。本次端侧开发不得修改地面站代码。

地面站 v0.13.1 已有多设备选择、`_ActiveJob`、每设备独立 session、融合算法和地图保存。本次不得重复设计或修改这些能力；真实融合仍在指控平台完成。现有 start 已发送 `job_id`、`role`、`primary_device_id`，但尚未完整发送 `participant_device_ids`、`start_at_ns`、`slice_duration_ns`，stop 也尚未完整发送 `job_id`、`stop_at_ns`，因此当前地面站不能直接启动严格模式的新包。

## 2. 必需协议扩展

1. `start_mapping` 保留既有 `job_id`、`role`、`primary_device_id`，增加 `participant_device_ids`、`start_at_ns`、`slice_duration_ns`。
2. 同一 `_ActiveJob` 的所有设备必须收到完全相同的 `job_id`、参与集合、`start_at_ns` 和 `slice_duration_ns`；每台设备的 `session_id` 继续独立。
3. `participant_device_ids` 至少包含两台不同设备，必须包含主设备和当前接收设备；`role` 必须与 `primary_device_id` 对应。
4. `start_at_ns` 使用绝对 UTC 纳秒，并留出网络、检查和订阅提前量。地面站应先确认设备时钟健康，再对全部参与设备发送同一开始时间。
5. `stop_mapping` 增加相同 `job_id` 和绝对 `stop_at_ns`，并要求提前下发。所有仍参与设备应收到同一停止时间。
6. 继续复用 `ccs-map-stream-v1`、schema 1、UDP 14561/14562、MessagePack、zlib 和独立 sequence；新增字段属于兼容扩展。

建议 start 新增字段示例：

```text
job_id:                  已有逻辑任务 ID
role:                    primary | secondary
primary_device_id:       主设备 ID
participant_device_ids:  本次参与设备 ID 完整集合
start_at_ns:              统一绝对开始时间
slice_duration_ns:        统一切片时长，可在端侧配置上下限内修改
```

## 3. 上行切片处理

1. `CloudFrameAssembler` 保持现有帧 CRC32、解压字节数、点数和坐标变换校验，同时保存并校验附加字段：`job_id`、`slice_id`、`slice_start_ns`、`slice_end_ns`、`frame_index`、`frame_count`、`partial`、`error_tail`、`truncated`、`pose_before_stamp_ns`、`pose_after_stamp_ns`、`pose_max_error_ns` 和 `pose_interpolated`。
2. 同一帧的所有 chunk 上述元数据必须一致；不一致时丢弃整帧。附加字段不改变现有点云重组和变换算法。
3. 地面站在现有 `_ActiveJob` 内按 `device_id/session_id/slice_id` 汇总，等齐参与设备或达到地面站切片超时后，再进入既有融合流程。不能把不同 job、session 或窗口的帧静默混合。
4. `slice_empty` 表示该设备在此窗口没有有效点云；`SLICE_TRUNCATED`/`truncated=true` 表示资源截断；`partial=true` 是停止边界的不完整尾片；`error_tail=true` 是错误结束前尽力上传的尾片。
5. 地面站按 `stop_at_ns` 对已接收帧做第二次时间过滤。迟到 stop 时机器人会报告 `STOP_TIME_MISSED`、`stop_at_ns` 和 `max_uploaded_stamp_ns`；已上传数据无法由 UDP 撤回，越界帧必须由地面站剔除。

## 4. 状态和 UI 兼容

- 复用现有多机创建向导、设备级状态、降级处理和正式地图提交，不新增第二套 UI 或任务模型。
- 在设备级状态中显示 armed、mapping、stopping、slice_empty、slice_complete、error 和 standby 结果。
- 开始前若任一设备拒绝完整联合字段，应按既有任务失败/剔除策略处理，不能退回旧单机 start 让新包绕过联合约束。
- 切片时长应作为任务参数传入并在所有参与设备 ACK 的 `actual_parameters` 中核对一致。

## 5. 可靠性边界

首版仍为 UDP 尽力传输；未来 ACK、缺片请求和选择性重传应单独设计，不能在本次兼容补字段中隐式改变协议可靠性。v0.13.1 已有 UI、`_ActiveJob`、多 session、融合算法和地图保存均属于环境基线，不属于本端侧包的修改交付。

## 6. 建议兼容验收

1. 两台不同机器人收到相同 job/参与集合/开始时间/切片时长和独立 session。
2. 同一绝对时间戳在两机上产生相同 slice ID 和窗口边界。
3. 空片、完整片、截断片、正常尾片和错误尾片均能归入正确设备/session/slice。
4. 提前 stop 后只融合 `sample_stamp_ns < stop_at_ns` 的帧；模拟迟到 stop 验证二次过滤。
5. 单设备掉线仍复用现有降级策略；主设备失败仍复用现有中止规则。
6. 最终结果继续由现有融合算法和地图仓储提交，不由端侧生成正式地图。
