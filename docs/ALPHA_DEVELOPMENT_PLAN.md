# Alpha 版本总体开发计划

## 1. 目标与边界

本计划以地面站 v0.13.1 和现有 `ccs-*-v1` 协议为基线，目标是形成可部署、可联调、可追溯的首个 Alpha 版本。设备类型模板、地图融合插件、已保存地图 PCD/PGM 同步融合、PGM 生成、地图交互和主题属于地面站本地能力；PGM 产物下载是 `ccs-map-stream-v1` 的可选扩展。

### 1.1 Alpha 必须交付

- 一台参考端侧设备的 MQTT、UDP 遥测、RTSP、实时建图和任务控制闭环。
- 两台模拟或 localhost 端侧设备的多设备任务、冲突检查、统一调度和多 session 地图融合测试。
- Windows 10/11、Ubuntu 20.04、Ubuntu 22.04 的地面站启动和回归验证。
- Ubuntu 20.04 + ROS1 Noetic 的端侧 catkin 构建、传感器话题联调和部署说明。
- 需求、接口、状态矩阵、故障处理、兼容性和已知风险文档完整。

### 1.2 不作为 Alpha 可运行门禁

- Ubuntu 22.04/24.04 上 ROS2 Humble/Jazzy 的完整端侧包实现。
- MQTT/UDP/RTSP 的认证、TLS、ACL、拥塞控制和公网部署。
- 面向所有设备型号的通用动力学控制、避障和飞行策略。

## 2. 工作流与依赖

| 工作流 | 主要内容 | 前置条件 | 交付证据 |
| --- | --- | --- | --- |
| W1 基线冻结 | 需求、状态、协议、端口、兼容矩阵 | 当前代码和文档盘点 | 需求文档、状态矩阵、接口核对记录 |
| W2 设备能力 | 可扩展类型、能力、标定、预览、统一标记 | 设备模型和配置 schema | 配置迁移、UI 测试、标记坐标测试 |
| W3 地图增强 | 多设备 session、坐标校验、融合、PGM 后处理 | 14561/14562 协议稳定 | 多设备模拟测试、融合样例、回滚测试 |
| W4 任务闭环 | 运动控制适配器、真实反馈、安全停止 | 任务协议和 ROS command/feedback | Noetic 适配器、状态机和实机日志 |
| W5 发布工程 | Noetic 构建、桌面依赖、启动/安装、监控 | W2-W4 接口稳定 | 三平台检查表、构建产物、部署脚本 |
| W6 参考设备 | 单设备全链路实机联调 | W4/W5 完成 | 实机验收报告、抓包和日志 |
| W7 发布审查 | 故障注入、性能、文档、风险关闭 | 全部 Alpha 功能 | Alpha checklist、已知问题和发布记录 |

依赖顺序为：身份/配置 -> 通信契约 -> 设备与地图坐标 -> 任务执行适配器 -> 平台发布 -> 实机闭环。协议 v1 在此过程中不做破坏性变更。

## 3. 详细任务与完成标准

### W1：需求、接口和状态冻结

- 对照代码、测试、配置、README、变更记录和端侧包，逐项标记“代码已完成/协议测试已完成/实机未验证/Alpha 必须完成”。
- 复核 MQTT 1883、UDP 14560-14564、RTSP 8554 的方向、来源校验、超时、重试、资源上限和数据真值边界。
- 冻结设备 ID/IP、地图 frame、任务 frame、descriptor hash、revision、session 和 UTC 时间规则。
- 交付需求文档、接口差异清单和待验证证据表。

### W2：设备能力与坐标基础

- 将固定设备类型改为可扩展类型/能力目录，保留已有配置向后兼容迁移。
- 增加设备能力、传感器、执行器、预览来源、默认坐标系和状态卡绑定。
- 设计并实现设备间初始坐标关系、标定版本和校验状态。
- 统一地图页、任务页和指控大屏的设备 3D 标记数据结构。
- 增加二维视频/图像预览的加载、断流、无媒体和权限失败状态。

完成标准：任意新设备类型可创建和保存；未标定设备不能参与跨设备融合；同一设备标记在三页面的位置和状态一致。

### W3：多设备地图与 PGM

- 地面站为每台端侧设备建立独立实时建图 session，并记录设备、地图、返回地址、标定和统计。
- 增加多 session 的开始/停止/超时/中断恢复和资源隔离。
- 对点云执行统一 frame 检查、外参应用、配准前后质量检查和体素融合。
- 增加 PCD 后处理、PGM 生成/导入、栅格拼接、占据阈值和未知区域处理。
- 维护地图 fingerprint；图层或坐标变化后要求任务重新复核。

完成标准：两台模拟设备可并行上传，错误 frame 或标定被拒绝，部分 session 失败不会损坏其他 session，正式地图提交具备原子回滚。

### W4：任务真实执行闭环

- 实现参考设备的 `TaskExecutionCommand`/`TaskExecutionFeedback` 适配器，不让 `epgeneral_task_control` 直接操作飞控。
- 验证 prepare/chunk/commit/execute/cancel/stop 及 revision、CRC、缺片补发和幂等逻辑。
- 验证 UTC scheduled、scheduled/running/completed/stopped/failed 状态和航点进度。
- 在适配器失联、反馈超时、节点重启和用户停止时发送安全 STOP/CANCEL，并释放地面站设备锁。

完成标准：参考设备可完成至少一条两航点以上任务，地面站收到真实状态/进度，停止操作在超时范围内进入安全状态。

### W5：平台和部署

- 锁定地面站 Python、PySide6、Qt Multimedia、NumPy、VisPy、pypcd4 和 MessagePack 版本范围。
- 提供 Windows 10/11 和 Ubuntu 20.04/22.04 的虚拟环境、启动脚本、依赖检查和日志位置。
- 提供 Ubuntu 20.04 + ROS Noetic catkin 构建、source、launch、systemd/tmux 运行说明。
- 验证 OpenGL 不可用时监控、配置、任务和网络模块仍可用。
- 增加 NTP、端口、防火墙、设备身份和 descriptor hash 的启动前检查。

完成标准：四类地面站/端侧启动检查可重复执行，失败时给出可定位错误，不产生半成品配置或地图。

### W6-W7：联调、故障注入与发布审查

- W6 在参考设备上完成 MQTT、14560、RTSP、14561/14562、14563/14564 全链路。
- W7 注入乱序、重复、缺片、CRC 错误、错误 IP、序列回退、端口占用、进程重启、话题超时、时钟漂移和磁盘写入失败。
- 记录吞吐、延迟、CPU、内存、点云帧率、任务状态延迟和长时间运行结果。
- 逐项关闭 Alpha 门禁；剩余问题必须有严重度、影响、临时规避和 Beta 目标。

| 层级 | 环境 | 必测内容 |

| 跨平台回归 | Win10/11、Ubuntu20/22 | 启动、端口、文件编码、Qt Multimedia、OpenGL 降级 |

## 5. 风险和发布门禁

| 风险 | 影响 | Alpha 控制措施 |
| --- | --- | --- |
| 运动控制适配器依赖真实设备 | 任务无法闭环 | W4 提前锁定一台参考设备和适配器负责人 |
| 坐标/标定错误 | 地图和任务安全风险 | frame、标定版本和地图 fingerprint 强制校验 |
| UDP 不可靠 | 数据缺失或状态误判 | CRC、分片、幂等、超时、检查点和明确告警 |
| OpenGL/Qt Multimedia 差异 | 地面站功能降级 | 启动探测、离屏测试、非三维模块保持可用 |
| Melodic/Noetic 文档冲突 | 部署失败 | Alpha 以 Noetic 为准，Melodic 仅保留维护说明 |
| Python 环境不可复现 | 无法安装和测试 | 固定版本、依赖检查、重建虚拟环境后再发布 |
| 可信内网无认证 | 网络攻击风险 | Alpha 明确限制部署范围，后续加入认证/TLS 计划 |

Alpha 发布门禁：所有 Alpha 必做项有代码、自动化测试或实机证据；一台参考设备全链路通过；多设备流程通过模拟/localhost；协议 v1 未破坏；文档、已知风险和回滚步骤齐全。
