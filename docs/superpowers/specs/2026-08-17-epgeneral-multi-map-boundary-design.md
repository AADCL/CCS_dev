本文把已冻结需求和现状审计转换为明确的软件边界、影响范围和不可修改项。本文不是 Step 5 正式开发路线，不包含编码授权。

## 2. 功能分类

本功能同时属于：

- D：ROS 端侧功能包；
- F：Protocol 兼容扩展；
- H：配置功能。

本次不属于地面站内部模块、地面站算法、地面站 UI、Repository 或持久化扩展。

## 3. 已选择方案

采用“独立源码复用”：

- 新增独立目录 edge_side_pkg/EPGeneral_multi_map；
- ROS package 名固定为 epgeneral_multi_map；
- 复用或适配旧包中已经验证的配置解析、协议、点云处理和会话清理思路；
- 新包内部保存自己的实现和测试；
- 新包运行时不得导入或依赖 epgeneral_map_stream；
- 不抽取新的公共核心包；
- EPGeneral_map_stream 的源码、配置、测试和行为保持不变。

该方案允许新包独立部署，同时保留未来合并回旧包的可追溯结构。

## 4. 部署边界

- 运行环境：Ubuntu 20.04、ROS1 Noetic、catkin、系统 Python 3.8。
- 纯 Python 核心兼容 Python 3.8 及以上。
- 每台参与机器人运行一个活动实例。
- 真实联合建图至少需要两台物理机器人。
- EPGeneral_multi_map 与 EPGeneral_map_stream 都使用 UDP 14561，因此不得同机同时运行。
- 单机器人旧建图启动 epgeneral_map_stream；联合采集启动 epgeneral_multi_map。
- 端侧只采集、时间配准、切片和上传；跨机器人配准与融合由指控平台完成。

## 8. 新包内部组件边界

### 8.1 配置层

读取共享设备身份和新包 YAML。校验网络、ROS 话题、通用位姿消息字段路径、frame、外参、同步容差、切片时长、0.2 秒默认迟到容忍期、时钟阈值和资源上限。

### 8.2 协议层

负责既有信封的编解码、字段校验、分片、zlib 和 CRC32。联合任务与切片语义只作为既有消息 payload 的扩展字段。

### 8.3 会话控制器

管理 standby、armed、mapping、stopping 和清理流程。负责请求幂等、单活动 session、统一开始、计划停止、异常尾片和复位。

### 8.4 位姿缓冲与插值器

从配置指定的通用 ROS 消息中提取时间、位置和四元数。优先使用点云时间戳前后的位姿插值；无法在容差内配准的点云单帧丢弃。

### 8.5 切片收集器

根据 start_at_ns 和切片时长计算确定性的绝对窗口。帧以自身时间戳归属窗口；窗口结束后等待迟到容忍期再封片。当前切片内保留原始 PointCloud2 和同步位姿，发送后释放。

### 8.6 切片处理器

完整片、正常停止尾片和错误尾片统一通过同一接口。首版实现为透传，不新增滤波、去动态目标或运动补偿。

### 8.7 帧预处理与上传器

沿用现有距离过滤、体素降采样、频率和点数限制。逐帧输出 XYZ，每个 cloud_chunk 带有所属切片的共同元数据；切片完成或空片错误使用既有 session_status 表达。

### 8.8 统计与监控

统计无效帧、同步失败、迟到帧、截断、空片、输入超时和已上传最大时间戳，并通过 ACK、heartbeat、status 和日志对外报告。

## 9. 数据流

### 9.1 开始

1. 接收并验证包含 collaboration_id、参与设备集合、map_id、独立 session_id、start_at_ns 和切片时长的开始指令。
2. 校验本机身份、设备数量、时间范围、参数上限和输入可用性。
3. 提前订阅点云和位姿并进入 armed。
4. armed 阶段允许缓存位姿，但不收集 start_at_ns 之前的点云。
5. 到达统一开始时间后进入 mapping。

### 9.2 切片

1. 点云按消息时间戳归入绝对窗口。
2. 为每帧匹配或插值唯一位姿。
3. 窗口结束后等待默认 0.2 秒迟到容忍期，该值可由 YAML 配置。
4. 合法迟到帧仍归入原窗口；超过期限的帧丢弃并计数。
5. 封片后通过透传处理器和既有帧预处理。
6. 上传逐帧点云、位姿和共同切片元数据。
7. 发送完成后立即释放切片，不等待 ACK。

### 9.3 停止

提前收到停止指令时，端侧继续采集到 stop_at_ns，只保留该时刻之前的数据，封闭并上传 partial=true 尾片，然后释放订阅和内存并回到 standby。

## 10. 异常和兼容策略

- 非法联合指令：拒绝并返回既有 command_ack，不创建会话。
- 旧开始指令：因缺少联合字段而明确拒绝，不降级为单机器人建图。
- 错过开始时间：上报 start_time_missed 语义并复位。
- 单帧错误：只丢弃该帧并累计统计。
- 输入源超时：尽力上传已有有效错误尾片，上报 error 后复位。
- 空窗口：不上传空点云，只发送切片错误状态。
- 单片超限：停止接收当前窗口的新帧并标记 truncated=true，下一窗口恢复。
- UDP 丢包：只能通过分片计数和 CRC 检测，首版不重传。
- 新旧包同时启动：后启动者因 UDP 14561 占用而失败并明确记录，不自动换端口。
- 节点重启：内存切片不可恢复，节点重新进入 standby。

### 10.1 迟到停止

采用“端地共同截断”：

- 指控平台原则上应提前发送 stop_at_ns；
- 若停止指令迟到，端侧丢弃尚未上传且时间戳不小于 stop_at_ns 的帧；
- 端侧上报 stop_time_missed、stop_at_ns 和已上传最大时间戳；
- 已经通过 UDP 发出的数据无法撤回；
- 未来地面站必须再次按 stop_at_ns 过滤已收到的越界数据。

## 11. 测试边界

自动化测试应覆盖：

- 配置、设备身份和联合指令校验；
- 位姿字段读取、四元数处理和前后位姿插值；
- 绝对窗口、确定性切片 ID 和迟到容忍；
- 完整片、停止尾片、错误尾片与空片；
- 帧数、点数和内存上限；
- start/stop 幂等、busy、错过开始和迟到停止；
- 既有预处理行为与透传处理器；
- MessagePack、zlib、CRC32 和 1400 字节分片；
- 单实例 localhost UDP 契约；
- Python 3.8 及以上语法和纯 Python 核心。

以下内容不能由当前 Windows 工作区测试代替：

- Ubuntu 20.04、ROS Noetic catkin 构建；
- 真实 PointCloud2 和现场位姿消息；
- NTP/PTP 时钟质量；
- 两台物理机器人联合采集；
- 指控平台最终融合效果。

同机 localhost 测试只验证协议和单节点状态机，不得称为真实联合建图验收。
