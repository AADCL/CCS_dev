# 指控系统 Alpha 开发计划

## 1. 目标与工程原则

地面站以当前 PySide6 v0.15.1 为基线，继续复用现有仓储、设备类型模板、运行状态仓储、数据源、协议服务和页面边界。所有新增功能必须通过共享服务进入页面，禁止页面直接创建 MQTT/UDP socket 或复制任务状态机。

工程原则：

- 先冻结数据模型和接口，再扩展 UI。
- 静态配置、运行时快照、执行快照和审计日志分离。
- 位置显示、地图融合和任务执行分别校验坐标系，不隐式转换。
- 单个模块故障只影响对应能力，不阻止本地编辑、历史查看和其他通信模块。
- 保持 `ccs-udp-telemetry-v1`、`ccs-map-stream-v1`、`ccs-task-control-v1` 端口和字段兼容。

## 2. 模块计划

### 2.1 设备域

**现状**：设备 CRUD、资料编辑与 ID 引用迁移、ping、搜索/筛选、MQTT/UDP 状态、紧凑日志和 SRT/FFmpeg 生命周期已经存在；设备类型由模板管理。

**开发任务**：

1. ~~将 `DeviceProfile` 的 `device_type` 与能力目录解耦，支持自定义类型、能力集合、状态卡集合和可用端侧包声明。~~
2. ~~扩展 `devices.json` schema，提供旧 schema 原子迁移、未知能力降级和配置错误只读保护。~~
3. 增加设备坐标系、初始位姿、标定版本、标定有效期和 frame 校验。
4. 统一 `DeviceMapMarker`，向地图页、任务页和指控大屏提供相同的 ID、名称、位置、姿态、frame、状态和时间字段。
5. 维护 SRT 图像预览状态模型，覆盖 FFmpeg 缺失、协议不支持、连接、播放、失败和有限重试。

**验收**：新增一个非内置类型设备并重启软件后仍能读取；无标定关系时禁止跨设备融合；同一设备在三个页面的标记位置一致；视频切页和退出无残留播放器。

### 2.2 地图域

**现状**：地图仓储 schema 4、PCD/PGM 导入、VisPy 图层、离线插件融合、单机/多机实时建图、体素预览和中断会话已实现。

**开发任务**：

1. ~~将 `MapBuildingService` 的单 session 边界扩展为多 session 管理，每个 session 独立保存设备、地图、返回地址、参数、统计和生命周期。~~
2. ~~增加建图设备集合选择、并发 start/stop、部分设备失败、单设备超时和整体保存策略。~~
3. 增加 map/body/sensor frame、外参和地图 fingerprint 的一致性校验。
4. ~~在地面站实现标准插件前置检查、统一坐标融合和体素去重/质心统计。~~ 后续补充自动配准和质量报告。
5. ~~增加 PCD 投影 PGM、占据阈值和未知区域规则。~~ 后续补充 PGM mosaic 和基于传感器射线的 free-space 推断。
6. ~~保证多设备结果、旧正式地图和临时 session 均可回滚；失败设备不覆盖成功设备的检查点。~~
7. 让地图页、任务页和大屏复用同一图层和标记渲染接口。

**验收**：两台 localhost 设备并发上传时可独立暂停/失败；错误 frame/标定被拒绝；融合结果包含来源和统计；正式提交失败可恢复旧地图。

### 2.3 任务域

**现状**：任务列表、地图绑定、子任务、PCD/PGM 选点、XYZ 编辑、排序、冲突检测、审计、分片传输、统一调度、停止和状态接收已经实现。

**开发任务**：

1. 增加设备能力检查：没有任务控制包、IP 缺失、frame 不匹配、地图 fingerprint 变化或设备被其他任务锁定时禁止下发。
2. 完善 PGM free-cell 校验、航点数量/有限性/高度/速度范围和任务保存前错误定位。
3. 保持 `TaskExecutionService` 作为唯一下发执行入口，补齐取消、缺片补发、重试耗尽、心跳超时和进程重启日志。
4. 完善多设备冲突规则、强制执行理由审计和统一 UTC 启动前 ACK 门槛。
5. 将 14564 的状态/进度真值映射为任务卡、详情页、大屏和历史执行事件；14560 只用于实时位置标记。
6. 为参考设备适配器增加 command/feedback 连接状态和安全停止结果展示。

**验收**：单设备和多设备任务均能通过传输、调度、反馈和停止；旧 revision 被拒绝；缺片补发、设备锁和心跳超时可观测且可审计。

### 2.4 指控大屏域

**现状**：在线设备栏、状态摘要、60 秒趋势、PCD/PGM/叠加、设备位置/轨迹、全屏、地图/任务选择和开始/终止控制已实现。

**开发任务**：

1. 统一大屏与任务页的任务选择、地图联动、执行快照和停止入口。
2. 增加模块告警、设备告警、任务错误、建图告警和数据年龄的统一控制台摘要。
3. 完善所有在线设备的 marker/trail/frame 检查，缺少有效遥测时显示 stale/unknown 而非零点。
4. 增加大屏在无地图、无设备、无任务、UDP 中断和任务服务不可用时的空态与降级行为。
5. 验证 800x600、1024x768、1440x900 和全屏下文本、按钮、图层和状态无重叠。

**验收**：大屏不产生第二套任务状态；开始、终止和执行日志与任务页完全一致；设备离线后选择迁移稳定；模块故障不影响导航和本地查看。

### 2.5 通信与基础设施域

**开发任务**：

1. 检查 MQTT、UDP 14560/14562/14564 的绑定错误、端口占用、来源 IP 和设备身份匹配。
2. 保持 14560 的 descriptor hash 和 20/5/1 Hz 分级；保持 14561/14562 的 1400 字节上限、zlib/CRC32 和 session 校验；保持任务 800 字节分片和 revision 规则。
3. 统一模块状态、最后心跳、最后数据时间、重试次数、丢帧数和错误码。
4. 增加启动前配置检查：设备 ID/IP、descriptor、协议 ID、端口、地图/任务限制和时间来源。
5. 提供可信局域网部署提示，明确当前无认证/TLS/ACL；不在 Alpha 中引入破坏性安全改造。

### 2.6 发布与兼容性域

**开发任务**：

- 锁定 Python 3.10/3.11、PySide6、Qt Multimedia、NumPy、VisPy、pypcd4 和 MessagePack 版本范围。
- 提供 Windows 10/11 PowerShell 启动检查、日志路径和依赖诊断。
- 提供 Ubuntu 20.04/22.04 venv、X11/Wayland、OpenGL 检查和 systemd/桌面启动说明。
- OpenGL 初始化失败时保留设备、通信、任务和配置能力，地图/大屏三维显示给出明确错误。
- 将地面站测试分为纯 Python、Qt 离屏、localhost 网络和真实桌面 OpenGL 四类，不以单一环境结果代替全部验证。

## 4. 指控系统测试清单

- 配置：自定义设备类型、schema 迁移、重复 ID、非法 IP、缺少能力、标定版本冲突。
- 地图：PCD/PGM 边界、frame mismatch、双设备 session、缺片、CRC 错误、临时结果、回滚和 ZIP。
- 任务：2/500 航点边界、free-cell、revision、缺片补发、冲突强制、统一 UTC、停止和心跳超时。
- 通信：MQTT retained/Last Will、UDP sequence/session、来源 IP、端口占用和模块降级。
- UI：离屏页面、布局断点、空态、视频释放、地图/任务/大屏联动和 OpenGL 失败。
- 性能：20 Hz 遥测、5 Hz 建图预览、1 Hz 状态、60 秒趋势、长时间运行和内存增长。

## 5. 完成定义

指控系统工作项只有同时满足“实现、自动化测试或实机证据、错误处理、文档更新”才可从“部分完成”改为“完成”。纯 UI 占位、localhost 协议成功或静态配置存在，不能替代真实端侧验收证据。
