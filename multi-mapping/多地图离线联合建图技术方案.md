# CCS_dev 多地图离线联合建图技术方案

## 1. 文档目的

本文定义 CCS_dev 第一阶段多地图联合建图方案。产品语义为：

> 操作员在指控平台地图页面选择两张或多张已经保存的 PCD 地图，指定一张参考地图，系统根据设备摆放记录和点云重叠关系完成配准、全局优化、预览与质量检查；操作员确认后生成一张新的联合地图。

这里的“联合建图”是对已保存地图的离线配准与融合。输入地图可以来自不同设备、不同建图 session，也可以来自同一设备的不同批次。融合时设备不必在线，现有 `ccs-map-stream-v1` 实时建图协议不需要修改。

输入数量记为 `N`，必须满足 `N >= 2`。两张地图只是 N 图流程的最小情况，不设计独立的“双图专用”产品流程。

## 2. 工作区依据与现有缺口

本方案与工作区现有约束保持一致：

- [需求分析.md](../需求分析.md) 的 FR-MAP 输入是“设备集合”，要求每台设备具有独立 session，并在统一坐标系下进行点云配准和融合。
- [GROUND_STATION_DEVELOPMENT_PLAN.md](../docs/GROUND_STATION_DEVELOPMENT_PLAN.md) 要求设备具备初始位姿、标定版本和 frame 校验，无标定关系时禁止跨设备融合。
- [map_page.py](../ccs_monitor/pages/map_page.py) 已用 `selected_map_ids` 集合保存多选状态，不需要另建地图选择页面。
- [map_repository.py](../ccs_monitor/map_repository.py) 的 `creator_devices` 已支持设备集合，但当前地图 schema 3 还没有多地图融合来源、设备摆放和全局位姿数据。
- [map_building.py](../ccs_monitor/map_building.py) 已按 `map <- body <- sensor` 变换点云，并提供体素质心累积器和 PCD 写入能力，可以复用于最终融合。

现有工作区只提出“设备间初始坐标关系和地图坐标标定”，没有给出现场设备如何摆放、如何记录初始位姿。端侧 `mapping.yaml` 中的 `body_from_sensor` 只是传感器相对本机机体的安装外参，不代表设备之间的相对位置。本方案在第 4 节补齐该操作约束。

## 3. 范围

### 3.1 本阶段包含

- 在指控平台选择两张或多张带有效 PCD 的已保存地图。
- 明确指定一张参考地图，其坐标系作为联合地图坐标系。
- 读取设备摆放/标定记录作为初始位姿；缺少记录时允许人工输入或自动全局配准。
- 建立地图重叠图，对候选地图对执行粗配准、精配准和双向质量评估。
- 当 `N >= 3` 时建立位姿图，利用可靠边和回环边进行全局优化。
- 以不同颜色预览所有输入地图在参考坐标系中的位置。
- 所有地图通过质量门槛并经操作员确认后，使用全量点云生成一张新地图。
- 记录所有输入地图指纹、设备摆放、全局变换、配准边、参数和质量指标。
- 输入地图只读；失败、取消或源地图变化时不发布半成品。

### 3.2 本阶段不包含

- 多设备同时在线采集和实时拼接；该能力仍由多 session 建图计划单独实现。
- 修改端侧 ROS 节点、UDP 端口或 `ccs-map-stream-v1` 消息格式。
- PGM 栅格地图配准、重采样和拼接。
- 自动替换任务当前引用的地图。
- 跨主机分布式任务编排或云端配准服务。
- 对动态目标或建图期间发生明显变化的场景做非刚体融合。

## 4. 设备摆放与数据采集约束

### 4.1 摆放目标

设备摆放不是为了让设备的 IP、frame 名称或起点看起来相同，而是为了满足以下两个条件：

1. 能得到设备地图相对统一场地坐标系的初始位姿；或
2. 相邻地图包含足够且可辨识的共同几何结构，使全部地图形成连通的重叠图。

只要每张地图能通过一条或多条可靠边连接到参考地图，就不要求所有地图都与参考地图直接重叠。

~~~text
地图 B ──重叠/标定── 地图 A（参考）──重叠/标定── 地图 C
                         │
                    重叠/标定
                         │
                       地图 D
~~~

上图是有效的连通摆放。若地图 D 与任何其他地图均无共同区域，也没有测量位姿，则不能参与本次联合建图。

### 4.2 推荐摆放方式

#### 开阔区域或房间

- 选择一台设备作为现场参考，在稳定且可复现的位置设置起点，标记坐标原点、`+X` 朝向和竖直方向。
- 其他设备分布在待建区域周边或不同入口，传感器有效视场朝向共同区域。
- 相邻设备的采集区域必须重叠，重叠区优先包含墙角、立柱、门框、设备轮廓等非对称三维结构。
- 避免所有设备只看到同一平面、重复货架或近似对称结构；必要时在共同区域布置固定标定板或反射标志。
- 传感器不得被机体、人员或临时物体大面积遮挡，设备在采集起始阶段应保持稳定。

#### 长走廊或狭长区域

- 设备沿走廊链式分布，相邻采集段保留共同区域。
- 每个共同区域应包含转角、门框或固定目标，避免仅用长直墙进行配准。
- 首尾地图有共同区域时将其作为回环约束；没有回环时必须保留实测初始位姿，降低累计漂移风险。

#### 移动机器人或无人机

- “摆放位置”指每次建图 session 的启动位姿，不要求设备整个建图过程静止。
- 记录每台设备启动时的位置和朝向；规划路径时让相邻设备的路线边界或起止区域有共同扫描区域。
- 多台设备可以在不同时间采集，但场景中的固定结构必须保持不变；移动物体不能作为配准依据。

重叠比例不写成适用于所有现场的硬常量。Alpha 数据采集可把有效几何重叠约 30% 作为建议起点，最终以真实数据的对应数量、双向 fitness 和配准残差确定门槛。

### 4.3 三种初始位姿来源

按可信度从高到低支持：

1. **共同场地坐标系**：RTK、全站仪、动捕或已标定定位系统直接给出每张地图相对 `site` frame 的位姿。
2. **人工测量摆放**：测量各设备相对参考设备的 `x/y/z/roll/pitch/yaw`，并记录测量方法和误差。
3. **未知摆放自动配准**：没有可靠位姿时，通过点云特征寻找重叠边；此模式仍要求重叠图连通且场景具有可辨识结构。

frame 名称相同不能证明物理原点相同，也不能自动采用单位矩阵。只有明确确认所有地图共享同一物理原点和方向时，才允许使用恒等初值。

### 4.4 必须记录的摆放数据

每张输入地图应保存或在联合建图对话框中补录：

- `map_id`、建图 `session_id`、设备 ID 和采集时间；
- 地图 frame、机体 frame、传感器 frame；
- `body_from_sensor` 标定版本；
- 启动时的 `map_from_body_start`；
- 可选的 `site_from_body_start`；
- 位姿来源：`shared_frame`、`surveyed`、`manual`、`identity_confirmed` 或 `unknown`；
- 测量单位、估计误差、标定版本和记录人。

若同时具有 `site_from_body_start` 和 `map_from_body_start`，地图在场地坐标系中的初值为：

~~~text
T_site_from_map_i = T_site_from_body_start_i · inverse(T_map_i_from_body_start_i)
~~~

相对参考地图的初值为：

~~~text
T_reference_from_map_i = inverse(T_site_from_map_reference) · T_site_from_map_i
~~~

所有平移使用米，角度输入使用度；进入算法层后转换为弧度。四元数顺序沿用工作区协议的 `x/y/z/w`。

## 5. 指控平台用户流程

1. 操作员进入地图页面并切换到编辑模式。
2. 选择 `N >= 2` 张带有效 PCD 的地图，点击“联合建图”。
3. 对话框列出所有输入地图、来源设备、frame、摆放/标定状态和文件状态。
4. 操作员指定一张参考地图和新地图名称。
5. 系统为每张非参考地图选择初始位姿来源；缺失信息时要求人工补录或选择自动配准。
6. 操作员可确认或编辑“哪些地图具有共同区域”的邻接关系；未填写时系统在资源上限内自动搜索候选地图对。
7. 点击“计算预览”，后台依次执行加载、候选边配准、重叠图连通性检查、位姿图优化、全局质量评估和预览采样。
8. 页面以稳定的不同颜色显示各地图，列出每张地图的全局位姿和每条配准边的质量。
9. 任一地图未连接、质量不合格或变换异常时禁止保存；操作员可修改初值、邻接关系，或返回选择页面移除失败地图后重新计算。
10. 全部输入地图通过门槛且操作员显式确认后，系统生成一张新的联合地图；所有输入地图保持不变。

系统不得静默忽略失败地图。如果选择了 N 张地图，发布结果必须包含全部 N 张；否则整次计算失败。

## 6. 坐标系与变换约束

### 6.1 全局变换命名

参考地图记为 `r`。每张地图 `i` 的全局变换统一命名为：

~~~text
T_reference_from_map_i
~~~

定义为：

~~~text
p_reference = T_reference_from_map_i · [p_map_i.x, p_map_i.y, p_map_i.z, 1]^T
~~~

参考地图满足：

~~~text
T_reference_from_map_reference = I
~~~

配准边 `i <- j` 使用 `T_map_i_from_map_j`。禁止在跨模块字段中使用方向不明确的 `transform`、`T12` 或 `map_transform`。

### 6.2 刚体约束

- 只允许 SE(3) 刚体变换，不允许缩放或反射。
- 矩阵必须是有限数值，最后一行近似 `[0, 0, 0, 1]`。
- 旋转矩阵必须近似正交且 `det(R)` 近似 1。
- RPY 固定采用 `Rz(yaw) · Ry(pitch) · Rx(roll)`。
- 结果地图 frame 采用参考地图 frame。
- 若地图 frame 语义不兼容且没有有效标定或配准边，直接拒绝融合。

## 7. 多地图配准与全局优化

### 7.1 算法流程

第一阶段使用同一条 N 图流程：

1. 加载并清洗所有 PCD，记录源地图指纹。
2. 为配准制作体素降采样副本，完整点云保持只读。
3. 根据摆放记录、人工邻接关系和特征匹配生成候选边。
4. 已知可靠位姿作为先验；未知边使用 FPFH + RANSAC 做全局粗配准。
5. 使用 GICP 对每条候选边做局部精配准。
6. 对点云配准边计算双向 fitness、RMSE、对应数量和信息矩阵；对标定先验边校验标定版本、有效期和不确定度，淘汰不合格边。
7. 检查合格边是否将所有地图连接到参考地图。
8. 以高置信边构造最大生成树得到初始全局位姿，并加入合格回环边。
9. 固定参考节点，执行鲁棒位姿图全局优化。
10. 重新评估每条边、每张地图和整体闭环残差。
11. 通过质量门槛后，把全局矩阵应用到所有完整点云并进行体素融合。

当 `N = 2` 时，位姿图只有两个节点和至少一条边，仍走相同实现，不维护第二套双图代码。

### 7.2 技术选型

采用 Open3D Python API 作为第一阶段后端：

- FPFH、RANSAC 用于未知初值的全局粗配准；
- GICP 用于局部精配准；
- PoseGraph 与 global optimization 用于 N 图一致性优化；
- registration evaluation 和 information matrix 用于边质量评估。

Open3D 使用延迟导入。未安装时只禁用联合建图入口，不影响现有地图浏览、导入、导出和单设备建图。只有真实性能数据证明局部配准是瓶颈时，再评估 `small_gicp`，本阶段不增加第二个运行时后端。

### 7.3 候选边策略

- 有共同场地坐标或测量摆放时，优先连接空间上相邻、包围盒可能重叠的地图。
- 操作员给出邻接关系时优先计算这些边，并补充可能形成回环的候选边。
- 完全未知摆放且地图数量较少时，可在配置上限内尝试两两粗配准。
- 任一地图至少需要一条通过门槛的边；只有生成连通图后才能优化和预览。
- 不要求每张地图直接配准到参考地图，避免大范围场景中错误地拒绝链式重叠。

### 7.4 全量点与配准点分离

- 降采样点只用于特征、配准、质量评估和 UI 预览。
- 最终结果必须使用全部有限原始点，经 `T_reference_from_map_i` 变换后加入 `VoxelMapAccumulator`。
- 输出体素大小与配准体素大小分开配置。
- 禁止把粗体素配准副本直接保存为正式地图。

## 8. 质量门槛

### 8.1 单边检查

位姿图中的边分为两类：

- 点云配准边检查正向和反向 fitness、inlier RMSE、对应数量、信息矩阵及退化情况；
- 共同场地坐标或实测标定边检查标定版本、有效期、测量误差和刚体约束，不要求没有空间重叠的地图伪造点云对应。

所有边还必须检查：

- 两端地图点数满足最低要求；
- 变换满足刚体约束；
- 精配准相对测量初值的修正量不超过其允许误差；
- 重复结构、低重叠和近似平面场景产生明确警告。

只看单向 fitness 会偏向“小地图落入大地图”，因此点云配准边必须进行双向评估。没有共同点云的地图只能依靠通过有效性检查的强标定边连接，不能依靠无误差说明的手工猜测位姿连接。

### 8.2 全图检查

- 合格边图必须包含全部输入地图并与参考节点连通。
- 每个非参考节点必须具有有限的 `T_reference_from_map_i`。
- 回环残差和优化前后位姿修正必须在阈值内。
- 每张地图至少有一条硬门槛通过的点云配准边或强标定边，不能仅靠弱先验悬挂在图中。
- 变换后的联合 bounds、点数和体素数必须在资源上限内。
- 输出点云必须非空且所有坐标有限。
- 提交前所有输入地图指纹必须与计算开始时一致。

### 8.3 人工确认

- 每张地图使用稳定、可区分的颜色，并显示颜色与地图名称对照。
- 可单独显示/隐藏地图和配准边，支持适配全部地图的联合包围盒。
- 展示全局位姿、边质量、连通图、闭环残差和所有警告。
- 操作员必须主动勾选“已检查全部地图空间关系”后才能保存。
- 硬门槛失败时不能强制保存；应返回调整初值、邻接关系或地图选择。

## 9. 模块设计

### 9.1 算法模块

新增 `ccs_monitor/map_fusion.py`，仅负责与 UI、仓储无关的算法：

- `FusionMapInput`
- `PlacementHint`
- `RegistrationEdge`
- `MapSetRegistrationResult`
- `FusionQualityReport`
- `validate_rigid_transform()`
- `build_manual_transform()`
- `register_map_set()`
- `optimize_pose_graph()`
- `fuse_full_resolution_clouds()`

接口接收地图列表、参考地图 ID、摆放初值和配置，返回每张地图的全局矩阵、边指标、整体指标及有上限的预览采样。算法模块不得修改 UI 或发布地图。

### 9.2 后台任务

新增 `ccs_monitor/map_fusion_worker.py`：

- 在线程中读取 PCD、执行 Open3D 和写候选 PCD；
- 按“加载—候选边—精配准—图优化—评估—全量融合”报告进度；
- 在地图对和阶段之间检查取消标志；
- 只向 UI 发送矩阵、指标和受上限约束的采样；
- 不在工作线程直接更新 Qt 控件或发布地图仓储。

### 9.3 地图页面

- 编辑模式下选择至少两张有效 PCD 地图时启用“联合建图”。
- 不设置输入地图数量的固定上限；内存保护由单图点数和输出体素上限负责。
- 对话框使用有序列表明确参考地图；不得依赖 `selected_map_ids` 集合遍历顺序。
- 当前查看器只有 base/live 两组点云，需增加按 `map_id` 管理的动态预览 visual，或等价的多颜色图层接口。
- 计算期间锁定输入，允许协作式取消；成功后刷新列表并选中新地图。

### 9.4 仓储发布

为 `MapRepository` 增加一个 N 图发布接口：

~~~python
commit_fused_map(
    *,
    name,
    reference_map_id,
    input_maps,
    expected_fingerprints,
    candidate_pcd_path,
    fusion_metadata,
) -> MapDefinition
~~~

该方法必须：

1. 串行化提交并复查全部输入地图。
2. 校验输入数量至少为 2、ID 唯一且参考地图属于输入集合。
3. 复查全部指纹、候选 PCD、新地图名称和元数据。
4. 在隐藏目录准备完整文件。
5. 在同一文件系统中以目录重命名原子发布。
6. 发布失败时清理暂存，任何输入地图保持不变。

接口不提供覆盖输入地图的参数。

## 10. 暂存与元数据

### 10.1 目录

~~~text
data/map_server/
  .fusion/<fusion_job_id>/
    candidate.pcd
    fusion.json
  .publish-<new_map_id>/
    map.pcd
    map.json
  <new_map_id>/
    map.pcd
    map.json
~~~

地图扫描必须忽略点号开头的目录。只有候选点云和 schema 都校验通过后，才把 `.publish-*` 原子重命名为可见目录。

### 10.2 地图 schema

地图 schema 从 3 升级到 4，并继续读取 schema 1、2、3。`last_fusion` 改为集合结构，不使用单数 `reference/source`：

~~~json
{
  "schema_version": 4,
  "map_id": "generated-id",
  "name": "联合地图",
  "frame_id": "reference-frame",
  "creator_devices": [],
  "last_fusion": {
    "fusion_id": "job-id",
    "created_at": "ISO-8601",
    "reference_map_id": "map-a",
    "input_maps": [
      {
        "map_id": "map-a",
        "fingerprint": "...",
        "frame_id": "map",
        "placement_source": "surveyed",
        "calibration_version": "site-v1"
      },
~~~

## 12. 测试方案

### 12.1 算法测试

- 2、3、5 张非对称合成点云施加已知 SE(3)，恢复全部全局位姿。
- 链式重叠中，末端地图不直接接触参考地图仍能成功。
- 加入回环边后，全局误差小于仅沿生成树累计的误差。
- 断开的重叠图必须失败，并准确列出未连接地图。
- 无重叠、低重叠、重复走廊、共面退化和错误人工初值不得静默成功。
- 变换方向、参考节点固定、刚体校验和全量融合分别测试。
- 输入含 NaN/Inf、点数过少或资源超限时行为明确。

### 12.2 仓储测试

- N 张输入成功发布新 ID，全部输入地图内容指纹不变。
- 任一输入地图在计算后变化时拒绝提交。
- 候选 PCD、矩阵集合或边元数据缺失时不产生可见地图。
- 名称冲突、写盘失败和取消不覆盖任何地图。
- schema 1–3 继续读取，schema 4 可读取、导出和重新导入。
- `.fusion`、`.publish-*` 不被 `load_all()` 识别。

### 12.3 UI 测试

- 少于两张地图时按钮禁用，选择 2、3、N 张有效地图时启用。
- PGM-only、PCD 缺失或错误地图不能进入联合建图。
- 参考地图切换后所有矩阵方向、颜色和预览同步更新。
- 每张输入地图可单独显隐，联合 bounds 能正确适配视角。
- 未连接地图和失败边有明确提示，不能保存部分结果。
- 取消后无新地图；成功后出现一张包含全部来源的新地图。
- 未安装 Open3D 时只禁用联合建图功能。

### 12.4 现场数据

至少准备：

- 两设备面对共同区域的高重叠地图；
- 三台以上设备围绕开阔区域形成回环；
- 沿走廊链式摆放、末端不直接重叠参考地图；
- 有全站仪/RTK 初值的基准数据；
- 完全未知摆放但重叠图连通的数据；
- 一张孤立地图导致整组失败的数据；
- 重复货架、低重叠、不同点密度和明显动态物体场景。

每组数据保存设备摆放图、测量值、允许误差、最终矩阵和独立工具对照结果。

## 13. 实施顺序

### 阶段 A：数据契约和摆放记录

- 固化 `T_reference_from_map_i`、摆放字段、输入地图集合和 schema 4。
- 在地图创建/建图结果中保存 session、frame、启动位姿和标定版本。
- 完成刚体、初值推导和地图指纹测试。

退出条件：指控平台能识别每张地图是否具有可用摆放/标定信息。

### 阶段 B：N 图算法

- 实现候选边、双向评估、连通性检查、最大生成树和位姿图优化。
- 复用现有 PCD 加载、体素累积和写入能力。
- 完成 2/3/5 图、链式重叠、回环和断图测试。

退出条件：N=2 与 N>2 使用同一入口，断图和错误配准不会输出候选正式地图。

### 阶段 C：安全仓储

- 实现全部输入指纹复核、隐藏暂存和原子发布。
- 增加 schema 4 兼容读取、导入和导出。
- 完成失败注入测试。

退出条件：任何失败路径都不修改输入地图，也不出现可见半成品。

### 阶段 D：界面闭环

- 增加 `N >= 2` 地图入口、参考地图和摆放/邻接编辑。
- 接入后台 worker、多颜色预览、图质量报告和人工确认。
- 用真实摆放数据调整参数与资源上限。

退出条件：操作员能完成“选择两张或多张地图—检查摆放—计算—预览全部地图—确认—生成联合地图”。

## 14. 验收标准

功能完成必须同时满足：

- 指控平台允许选择两张或多张有效 PCD 地图发起联合建图。
- 操作员明确指定参考地图，不依赖集合顺序。
- 方案和元数据明确记录设备摆放、启动位姿、frame 与标定来源。
- 所有输入地图形成连接到参考节点的重叠/标定图。
- N=2 与 N>2 使用同一配准和发布流程；N>=3 执行位姿图全局优化。
- 所有地图均有全局变换，任一地图失败时不发布部分结果。
- 配准边、全局质量门槛和人工确认均通过后才能保存。
- 最终结果使用完整点云进行体素融合，并生成一张新的可追溯地图。
- 输入地图保持不变；失败、取消和写盘故障不留下可见半成品。
- 旧 schema 地图可继续使用，Open3D 缺失不影响非融合功能。
- 现有单设备建图协议和端侧程序保持兼容。

## 15. 最终结论

CCS_dev 的联合建图入口应位于指控平台地图页面，输入是操作员选择的 `N >= 2` 张已保存 PCD 地图，而不是固定两张地图。

设备现场摆放必须保证“有可追溯的共同坐标初值”或“相邻地图重叠图连通”。系统把摆放记录作为配准先验，以点云边质量验证先验；对多张地图建立位姿图并做全局优化，再用全量点云体素融合生成一张新地图。任何未连接或质量失败的输入都使整次任务失败，不能被静默遗漏，也不能覆盖原地图。
